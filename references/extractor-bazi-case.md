# 命例提取器

你的任务是从分配给你的文本块中提取【结构化命例】。

**命例的定义**：书中用来论证某条规则的、带有完整四柱排盘的八字实例。命理书中的命例不是装饰——它是规则的**证据载体**。每个命例必须结构化到可以直接被检索和引用。

## 你要找的

命例分两种格式——完整命例（有四柱排盘）和简例（只有核心配置），两种都要提取：

**完整命例**：有明确四柱排盘（年/月/日/时天干地支）的实例

**简例（古代经典常见）**：没有完整四柱，但给出了关键配置信息（如"甲生寅月，四柱透庚""壬生午月，财官并透"）。只要包含判断逻辑就提取，不因缺少完整排盘而放弃。
> 简例在子平真诠评注、滴天髓等古代经典中占绝大多数，是规则佐证的核心来源。跳过简例等于跳过书中 90% 的命例证据。

## 你不要的

- 只有结论没有八字排盘的举例
- 泛泛而谈的"比如一个人八字中X多，就会Y"，没有具体排盘
- 作者虚构的假想场景（无具体干支）

## 处理要求

1. 先读 `references/bazi-model.md`，了解命例的归档格式和模型路径体系
2. 逐块处理分配给你的每一块，一块都不能跳过
3. 命例中出现的每条论断，都要尝试找到它在 bazi-model 中的对应路径
4. 遇到"如图X所示"而看不到图时，从前后文重建内容

## 记录格式

### 完整命例格式

```
## 命例 · <一句话标识>

### 排盘
- 年柱：<天干><地支> [纳音:如有]
- 月柱：<天干><地支> [纳音:如有]
- 日柱：<天干><地支> [纳音:如有]  ← 日干为日主
- 时柱：<天干><地支> [纳音:如有]
- 性别：<如有>
- 大运/流年：<书中给出的相关信息>

### 书中论断
<作者对这个八字的分析判断，原文摘录>

### 涉及规则
每条从该命例中体现的规则，必须带模型路径：
1. [Lx层级 > 具体节点 > ...] <规则内容简述>
2. [Lx层级 > 具体节点 > ...] <规则内容简述>

### 推理链
作者是怎么从八字一步步推导到结论的：
1. <步骤1>
2. <步骤2>
3. <步骤3>
→ 结论：<结论>

### 原文位置
第几块 / 第几章
```

### 简例格式（古代经典或配置不全的命例）

```
## 简例 · <一句话标识>

- 已知配置：<书中所给的四柱信息，哪怕只有日干+月令也写>
  例："日主甲木，生于寅月，四柱透庚"
- 流派/格局：<如有格局判断>
- 书中论断：<原文摘录>
- 支撑的规则：<这条简例在论证什么规则（规则名称或简述）>
- 模型路径：<Lx > ...>
- 原文位置：第几块
```

> 简例和完整命例在验证阶段的权重相同——都是一条可用的证据。

## 逐块回执

处理完后，在文件最后逐块写一行，分给你几块就写几行，不许合并、不许省略：

```
第 1 块：找到 1 个命例
第 2 块：无
第 3 块：找到 2 个命例
```
